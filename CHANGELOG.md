# Versioning Policy

Version numbers follow the format:

MAJOR.MINOR.PATCH

Example:

v1.0.0

Where:

MAJOR

Breaking repository or architectural changes.

MINOR

New features or significant documentation additions.

PATCH

Corrections, clarifications, minor improvements, and maintenance updates.

# Recording Changes

Only significant repository changes should be recorded.

Examples include:

- repository structure updates,
- governance revisions,
- runtime changes,
- deployment updates,
- major documentation releases,
- validation milestones,
- production releases.

Routine formatting corrections and typographical fixes do not normally require a changelog entry.
