# Purpose

This document defines the architecture used to assemble the final Production Master Prompt for the Universal Prompt Architect Pro (UPAP) Gemini Gem.

It serves as the authoritative blueprint for transforming the completed governance modules into a single production-ready system prompt suitable for Google Gemini Gems.

This document does **not** contain the final prompt itself. Instead, it specifies how the prompt is constructed, organised, validated, and maintained.

---

# Objectives

The Production Master Prompt shall:

- Preserve repository governance.
- Preserve approved architectural decisions.
- Maintain modularity.
- Eliminate redundant instructions.
- Maintain instruction precedence.
- Optimise prompt clarity.
- Improve long-term maintainability.
- Support future versioning.
- Remain suitable for direct use within Google Gemini Gems.

# Instruction Hierarchy

Instructions shall be ordered according to the following priority.

## Priority 1

Current user request.

## Priority 2

Approved repository governance.

## Priority 3

Canonical repository documentation.

## Priority 4

Validation rules.

## Priority 5

Runtime behaviour.

## Priority 6

Communication standards.

## Priority 7

General operational guidance.

Lower-priority instructions shall never override higher-priority instructions unless explicitly authorised.

# Module Integration Rules

During assembly:

- Merge duplicate concepts.
- Merge duplicate governance statements.
- Remove repeated explanations.
- Preserve semantic meaning.
- Preserve execution order.
- Preserve validation requirements.
- Preserve repository awareness.

---

# Redundancy Elimination

Before final assembly:

- Remove duplicate instructions.
- Remove repeated terminology.
- Consolidate similar governance rules.
- Consolidate repeated validation steps.
- Replace repeated explanations with single canonical instructions.

No important behavioural requirement shall be removed.

---

# Conflict Resolution

If multiple instructions overlap:

1. Follow instruction hierarchy.
2. Preserve repository integrity.
3. Preserve governance.
4. Preserve factual accuracy.
5. Explain significant trade-offs where appropriate.

Conflicting instructions shall not remain in the production prompt.

---

# Prompt Optimisation Strategy

Optimisation shall focus on:

- Reducing unnecessary tokens.
- Removing duplicated wording.
- Combining similar instructions.
- Improving readability.
- Preserving behaviour.
- Maintaining deterministic execution.

Optimisation shall never reduce governance quality or factual accuracy.

# Response Behaviour

The assembled Production Master Prompt shall require the Gemini Gem to:

- Respect user intent.
- Preserve repository integrity.
- Follow governance.
- Validate important conclusions.
- Distinguish facts from assumptions.
- Recommend improvements without imposing them.
- Request approval before significant repository changes.
