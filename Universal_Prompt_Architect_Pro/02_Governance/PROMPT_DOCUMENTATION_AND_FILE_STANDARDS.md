# Prompt, Documentation & File Standards

**Project:** Universal Prompt Architect Pro (UPAP)

**Module:** 02_Governance

**Repository Version:** v1.0.0 RC1.1

**Status:** Production

---

# 1. Purpose

This document defines the official standards for:

- Prompt engineering
- Repository documentation
- Markdown formatting
- File naming
- Directory organization
- Internal document consistency

These standards apply to all future repository content.

---

# 2. Guiding Principles

Every repository asset shall be:

- Accurate
- Complete
- Modular
- Consistent
- Version-controlled
- Repository-aware
- Production-ready
- Easy to understand

---

# 3. Prompt Engineering Standards

All production prompts shall:

- Clearly define the AI role.
- Define the project context.
- State the objective.
- Define scope boundaries.
- Include operating constraints.
- Specify expected outputs.
- State prohibited behaviours.
- Use structured headings.
- Be copy-paste ready.
- Avoid ambiguity.

Prompt changes should preserve backward compatibility whenever practical.

---

# 4. Documentation Standards

Repository documentation shall:

- Begin with a clear purpose.
- Use descriptive section headings.
- Follow a logical reading order.
- Explain technical concepts where necessary.
- Avoid duplicate content.
- Reference canonical documents rather than repeating them.
- Be written in professional, concise English.

---

# 5. Markdown Standards

Markdown documents should:

- Use hierarchical headings (`#`, `##`, `###`) consistently.
- Use tables for structured comparisons.
- Use fenced code blocks for examples.
- Use bullet lists for related items.
- Separate major sections with horizontal rules (`---`).
- Avoid excessive formatting.

---

# 6. File Naming Standards

Repository filenames shall:

- Use descriptive names.
- Use uppercase words separated by underscores where applicable.
- Match the document purpose.
- Avoid ambiguous abbreviations.
- Avoid duplicate names.

Examples:

- GEM_DEVELOPMENT_GOVERNANCE_POLICY.md
- KNOWLEDGE_UPLOAD_MATRIX.md
- VALIDATION_FRAMEWORK.md

---

# 7. Directory Organization Standards

Repository directories shall:

- Represent one primary responsibility.
- Avoid unnecessary nesting.
- Contain related documents only.
- Remain logically organized.
- Preserve the certified repository structure.

---

# 8. Internal Linking Standards

When referencing another repository document:

- Use its canonical filename.
- Do not duplicate the referenced content.
- Ensure references remain valid after repository updates.

Broken references should be corrected before release.

---

# 9. Copy-Paste Readiness

All production documents shall be immediately usable.

Avoid placeholder text unless clearly identified.

Examples should be complete and executable where applicable.

---

# 10. Consistency Standards

Repository content shall maintain consistent:

- Terminology
- Formatting
- Heading structure
- Naming conventions
- Writing style
- Version references

Consistency improves maintainability and reduces ambiguity.

---

# 11. Review Checklist

Before approving a repository document, verify:

- Purpose is clearly defined.
- Scope is complete.
- Formatting follows repository standards.
- References are accurate.
- No duplicate content exists.
- Version information is correct.
- Grammar and spelling have been reviewed.
