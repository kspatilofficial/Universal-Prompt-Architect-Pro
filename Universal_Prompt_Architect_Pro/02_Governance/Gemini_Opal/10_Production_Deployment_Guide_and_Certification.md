# Purpose

This document defines the standard deployment procedure for the Universal Prompt Architect Pro implementation targeting Gemini Opal.

Its objective is to ensure every deployment follows a repeatable, governed, validated, and repository-compatible process while remaining independent of undocumented Gemini Opal implementation details.

This document governs deployment methodology rather than platform-specific deployment mechanics.

---

# Deployment Objectives

Every deployment shall:

- Preserve repository integrity.
- Preserve governance.
- Maintain documentation consistency.
- Verify validation status.
- Support version traceability.
- Minimise deployment risk.
- Enable future maintenance.

---

# Deployment Principles

Every deployment shall follow these principles.

- Governance First
- Validation First
- Repository First
- Documentation First
- Traceability First
- Repeatability First
- Maintainability First

Deployment convenience shall never override governance.

---

# Deployment Prerequisites

Before deployment, verify:

- Repository is up to date.
- Governance documents are current.
- Documentation is synchronised.
- Validation activities are complete.
- Outstanding issues are documented.
- Version information has been updated.

Deployment shall not proceed if mandatory prerequisites remain incomplete.

---

# Repository Verification

Verify repository consistency.

Confirm:

- Folder hierarchy
- Naming conventions
- Version numbers
- Internal references
- Document relationships
- Governance structure

Repository inconsistencies should be resolved before deployment.

---

# Production Prompt Verification

Verify that the Production Master Prompt:

- Matches repository governance.
- Uses current terminology.
- Contains no conflicting instructions.
- Remains internally consistent.
- Reflects the current repository version.

Prompt verification shall occur before import into Gemini Opal.

---

# Documentation Verification

Confirm documentation includes:

- Repository path
- Version
- Status
- Purpose
- Compliance statement
- Structured sections
- End-of-document marker

Documentation quality shall remain consistent across the repository.

---

# Validation Verification

Confirm that:

- Requirements validation completed.
- Design validation completed.
- Workflow validation completed.
- Documentation review completed.
- Repository verification completed.

Deployment recommendations should follow successful validation.

---

# Deployment Workflow

The recommended deployment lifecycle is:

Repository Review

↓

Governance Verification

↓

Documentation Synchronisation

↓

Validation Verification

↓

Production Prompt Assembly

↓

Platform Configuration

↓

Functional Testing

↓

Acceptance Review

↓

Production Deployment

↓

Post-Deployment Review

Each stage should complete successfully before progressing to the next.

---

# Production Prompt Assembly

Assemble the Production Master Prompt using the approved repository documents.

Verify:

- Section order
- Instruction hierarchy
- Terminology consistency
- Governance consistency
- No duplicate content
- No conflicting guidance

Assembly should produce a single authoritative prompt.

---

# Platform Configuration

Configure Gemini Opal using only:

- Verified repository documentation
- Approved production prompt
- Documented configuration decisions

Do not rely on undocumented platform behaviour.

---

# Functional Testing

Perform representative testing using workflows that exercise:

- Workflow planning
- Workflow reasoning
- Repository awareness
- Validation behaviour
- Documentation generation
- Governance compliance

Testing should reflect expected operational use.

---

# Acceptance Criteria

A deployment may be accepted only when:

- Repository verification succeeds.
- Validation requirements are satisfied.
- Documentation is synchronised.
- Production prompt is current.
- No unresolved critical governance issues exist.
- Deployment objectives are achieved.

Acceptance decisions should be documented.

---

# Post-Deployment Review

After deployment, review:

- Behaviour consistency
- Documentation accuracy
- Repository compatibility
- Validation outcomes
- Identified improvement opportunities

Record findings for future repository revisions.

---

# Maintenance Strategy

Following deployment:

- Maintain semantic versioning.
- Document revisions.
- Preserve backward compatibility where practical.
- Review governance periodically.
- Keep repository documentation synchronised.

Maintenance activities should remain traceable.

---

# Version Management

Future repository revisions shall follow semantic versioning.

## Patch Releases

- Editorial improvements
- Formatting updates
- Minor clarifications

---

## Minor Releases

- Additional governance modules
- Expanded workflow guidance
- Validation enhancements
- Documentation improvements

---

## Major Releases

- Prompt architecture changes
- Governance restructuring
- Repository redesign
- Behavioural revisions

Every release shall include version documentation.

---

# Certification Checklist

Before certifying a deployment, confirm:

- Repository structure verified.
- Governance documents complete.
- Documentation synchronised.
- Validation completed.
- Production prompt assembled.
- Internal consistency verified.
- Version information updated.
- Outstanding issues documented.

All mandatory items should be satisfied before certification.

---

# Production Readiness Checklist

The implementation is considered production-ready when:

- Governance framework is complete.
- Repository documentation is complete.
- Validation framework is active.
- Production prompt is current.
- Deployment documentation is complete.
- Version control is established.
- Repository integrity is maintained.

Production readiness should be reassessed after significant revisions.

---

# Operational Constraints

The deployment process shall not:

- Assume undocumented Gemini Opal capabilities.
- Ignore validation failures.
- Deploy conflicting governance.
- Introduce undocumented behaviour.
- Bypass repository verification.
- Conceal deployment limitations.

---

# Continuous Improvement

Following deployment, improvements should focus on:

- Governance refinement
- Documentation quality
- Validation coverage
- Repository organisation
- Workflow maintainability
- Prompt clarity

Continuous improvement shall preserve repository stability.

---

# Production Certification

This deployment methodology is certified for use within the Universal Prompt Architect Pro repository provided that:

- Repository governance remains authoritative.
- Documentation remains synchronised.
- Validation activities remain active.
- Version control practices are followed.
- Future revisions remain documented.

This certification applies to the repository engineering process and does not certify undocumented Gemini Opal platform functionality.

---

# Compliance Statement

All deployments of the Universal Prompt Architect Pro implementation targeting Gemini Opal shall follow the methodology defined in this document.

Alternative deployment procedures may be adopted only when they are documented, technically justified, and remain consistent with repository governance.
