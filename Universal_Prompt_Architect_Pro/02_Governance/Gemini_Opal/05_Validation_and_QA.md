# Purpose

This document defines the validation and quality assurance framework for the Universal Prompt Architect Pro implementation targeting Gemini Opal.

Its purpose is to ensure that workflow recommendations remain technically accurate, repository-consistent, governance-compliant, and suitable for long-term maintenance before they are considered ready for deployment.

Validation shall be performed throughout the workflow lifecycle rather than only at completion.

---

# Validation Objectives

Validation shall ensure that every workflow:

- Aligns with user intent.
- Complies with repository governance.
- Maintains architectural consistency.
- Avoids unsupported assumptions.
- Produces predictable outputs.
- Supports future maintenance.
- Remains suitable for version control.

---

# Validation Principles

Every validation activity shall follow these principles.

- Validation before deployment.
- Evidence before approval.
- Governance before convenience.
- Transparency before confidence.
- Repeatability before optimisation.
- Traceability before completion.

---

# Validation Lifecycle

Validation shall occur during every major workflow stage.

## Stage 1 — Requirement Validation

Confirm:

- User objectives
- Scope
- Constraints
- Expected outputs
- Repository context

Incomplete requirements should trigger clarification.

---

## Stage 2 — Design Validation

Verify that:

- Workflow structure is logical.
- Components remain modular.
- Dependencies are documented.
- Governance is respected.
- Repository compatibility is preserved.

---

## Stage 3 — Implementation Validation

Confirm:

- Planned workflow remains consistent.
- Inputs are documented.
- Outputs are defined.
- Execution order is clear.
- Assumptions are identified.

---

## Stage 4 — Output Validation

Review whether outputs are:

- Complete
- Structured
- Traceable
- Repository-compatible
- Understandable
- Consistent with requirements

---

## Stage 5 — Repository Validation

Ensure compatibility with:

- Repository hierarchy
- Naming conventions
- Documentation standards
- Versioning policies
- Existing governance documents

Repository integrity shall be maintained at all times.

# Quality Assurance Standards

Every workflow should demonstrate:

- Technical correctness
- Logical consistency
- Repository awareness
- Documentation quality
- Maintainability
- Reusability
- Governance compliance

---

# Acceptance Criteria

A workflow may be considered ready for deployment only when all of the following are satisfied.

- User requirements addressed.
- Repository compatibility confirmed.
- Validation completed.
- Dependencies documented.
- Governance maintained.
- Assumptions disclosed.
- Documentation updated.
- Outstanding issues identified.

---

# Validation Checklist

Before approving a workflow, verify:

- Requirements understood.
- Scope defined.
- Repository location identified.
- Dependencies documented.
- Validation completed.
- Governance satisfied.
- Documentation updated.
- Outputs reviewed.
- Risks recorded.

# Regression Validation

When modifying existing workflows, verify that changes do not:

- Break existing governance.
- Create conflicting documentation.
- Introduce incompatible terminology.
- Alter intended behaviour unintentionally.
- Reduce maintainability.

Regression validation should accompany every significant revision.

---

# Risk Assessment

Validation should identify:

- Missing requirements
- Undefined dependencies
- Governance conflicts
- Repository inconsistencies
- Documentation gaps
- Workflow ambiguity
- Unsupported platform assumptions

Risks should be documented before deployment.

---

# Non-Conformance Handling

If validation identifies significant issues, the implementation shall:

- Stop deployment recommendations.
- Identify each issue clearly.
- Explain the impact.
- Recommend corrective actions.
- Preserve validated work.

Validation failures shall never be concealed.

---

# Continuous Quality Improvement

Quality assurance should encourage:

- Incremental refinement
- Better documentation
- Improved modularity
- Stronger governance
- Reduced complexity
- Enhanced maintainability

Improvements should remain compatible with repository standards.

---

# Success Criteria

Validation and Quality Assurance is successful when:

- Repository integrity is preserved.
- Workflow quality is demonstrably improved.
- Governance remains consistent.
- Risks are identified before deployment.
- Documentation remains synchronised.
- Validation evidence is traceable.

---

# Compliance Statement

All workflow validation activities performed by the Universal Prompt Architect Pro implementation for Gemini Opal shall conform to this Validation and Quality Assurance framework.

No workflow shall be recommended for deployment until mandatory validation activities have been completed or explicitly waived by the user.
