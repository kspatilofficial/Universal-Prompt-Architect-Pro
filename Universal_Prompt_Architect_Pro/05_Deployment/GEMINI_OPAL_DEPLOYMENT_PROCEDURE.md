# Gemini Opal Deployment Procedure

**Project:** Universal Prompt Architect Pro (UPAP)

**Platform:** Google Gemini Opal (Gem by Labs)

**Module:** 05_Deployment

**Repository Version:** v1.0.0 RC1.1

**Status:** Production

---

# 1. Purpose

This document defines the official deployment procedure for Universal Prompt Architect Pro (UPAP) within Google Gemini Opal (Gem by Labs).

The objective is to ensure that workflow-based deployments remain consistent with the certified repository, governance policies, and validation framework.

---

# 2. Scope

This procedure applies only to:

- Google Gemini Opal (Gem by Labs)
- Workflow-based implementations
- Certified repository versions

Gem Manager deployments are documented separately.

---

# 3. Prerequisites

Before deployment, verify:

- Repository certification completed.
- Repository version confirmed.
- Validation completed.
- Acceptance Testing completed.
- Deployment package prepared.
- Knowledge package prepared.
- Certified Opal Master Prompt available.

Deployment shall not proceed until all prerequisites have been satisfied.

---

# 4. Deployment Inputs

Required deployment assets include:

- Certified repository
- Opal Master Prompt
- Approved Knowledge Package
- Deployment documentation
- Validation records
- Repository version information

---

# 5. Repository Verification

Before creating or updating an Opal workflow, confirm:

- Repository version
- Certification version
- Module completeness
- Documentation synchronization
- Knowledge package version

Only certified repository assets shall be used.

---

# 6. Workflow Preparation

Before implementation:

- Define workflow objective.
- Identify required workflow nodes.
- Confirm repository dependencies.
- Review governance requirements.
- Review validation requirements.

Workflow design shall remain aligned with repository architecture.

---

# 7. Workflow Configuration

Configure the workflow using:

## Workflow Name

Use the approved repository naming convention.

---

## Workflow Description

Use the repository-approved production description.

---

## System Prompt

Use the certified Opal Master Prompt.

Do not modify the prompt during deployment.

---

## Knowledge

Attach only the approved knowledge package.

Maintain the approved upload sequence.

---

## Workflow Logic

Implement only approved workflow behaviour.

Experimental workflow changes shall be documented and validated before production use.

---

# 8. Recommended Knowledge Upload Order

Attach repository knowledge in the following order:

1. Runtime
2. Governance
3. Behavior
4. Knowledge
5. Optional supporting documentation
6. Deployment documentation (only if required)

Maintain version consistency throughout the workflow.

---

# 9. Workflow Validation

After deployment, verify:

- Workflow loads successfully.
- System Prompt is applied correctly.
- Knowledge package is attached.
- Workflow logic executes as intended.
- Repository version matches deployment.
- Governance rules are followed.
- Runtime behaviour is correct.

---

# 10. Deployment Completion Checklist

Confirm:

- Workflow deployed successfully.
- Validation completed.
- Repository version recorded.
- Knowledge package version recorded.
- Deployment date recorded.
- Operator recorded.
- Deployment status updated.

---

# 11. Deployment Restrictions

During deployment:

- Do not edit certified repository documents.
- Do not modify the certified Opal Master Prompt.
- Do not attach uncertified knowledge.
- Do not mix repository versions.
- Do not bypass validation.
- Do not introduce undocumented workflow behaviour.

---

# 12. Relationship to Other Modules

This deployment procedure depends upon:

- Deployment Policy & Strategy
- Governance Module
- Knowledge Module
- Validation Module

All Opal deployments shall comply with these repository modules.
