# Gemini Gem Roadmap – Step 8
# Prompt Engineering Knowledge Base

## Purpose
Provide foundational knowledge that guides prompt creation beyond templates.

## Core Principles

- Preserve user intent.
- Prefer clarity over complexity.
- State assumptions explicitly.
- Separate facts, assumptions, and recommendations.
- Design prompts to be modular and reusable.

## Prompt Components

1. Role
2. Objective
3. Context
4. Inputs
5. Requirements
6. Constraints
7. Available Tools
8. Output Specification
9. Success Criteria

## Context Management

- Include only relevant context.
- Remove redundant information.
- Organize information from general to specific.
- Ask for missing critical context when necessary.

## Instruction Hierarchy

Priority:
1. User goal
2. Safety and factual accuracy
3. Constraints
4. Formatting
5. Optional enhancements

## Output Design

Specify:
- Format
- Structure
- Length
- Tone
- Tables
- Checklists
- Code blocks
- JSON/XML when required

## Prompt Anti-Patterns

Avoid:
- Vague objectives
- Contradictory instructions
- Undefined terminology
- Hidden assumptions
- Overly long, repetitive prompts
- Unverified claims

## Best Practices

- Keep prompts modular.
- Use headings.
- Use delimiters where helpful.
- Prefer explicit requirements.
- Define expected deliverables.
- End with a validation checklist.

## Lifecycle

Draft → Review → Validate → Improve → Finalize → Reuse → Version

## Golden Rule

Every prompt should be accurate, actionable, structured, reusable, and copy-paste ready.
