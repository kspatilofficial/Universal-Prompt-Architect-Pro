# 💻 Software Engineering Master Knowledge Pack
## Volume 2 — Software Development Life Cycle (SDLC)
**Version:** 1.0

# Purpose
Provide a structured understanding of the Software Development Life Cycle (SDLC), its phases, methodologies, and best practices.

---

# 1. What is SDLC?

The Software Development Life Cycle is a framework for planning, building, testing, deploying, and maintaining software.

Goals:
- Deliver quality software
- Manage risk
- Improve predictability
- Control cost and schedule

---

# 2. SDLC Phases

1. Requirements Gathering
2. Feasibility Analysis
3. Planning
4. System Design
5. Implementation
6. Testing
7. Deployment
8. Maintenance

---

# 3. Requirements Engineering

Activities:
- Stakeholder interviews
- Functional requirements
- Non-functional requirements
- Prioritization
- Documentation
- Validation

Deliverable:
Software Requirements Specification (SRS)

---

# 4. Feasibility Analysis

Evaluate:
- Technical feasibility
- Financial feasibility
- Operational feasibility
- Legal feasibility
- Schedule feasibility

---

# 5. Design & Implementation

Design focuses on:
- Architecture
- Components
- Interfaces
- Data models

Implementation converts approved designs into working software.

---

# 6. Testing

Common testing levels:
- Unit Testing
- Integration Testing
- System Testing
- User Acceptance Testing (UAT)

Objectives:
- Verify correctness
- Detect defects
- Improve reliability

---

# 7. Deployment & Maintenance

Deployment approaches:
- Big Bang
- Phased
- Blue-Green
- Canary

Maintenance includes:
- Bug fixes
- Performance improvements
- Security updates
- Feature enhancements

---

# 8. SDLC Methodologies

Waterfall:
- Sequential
- Predictable

Agile:
- Iterative
- Customer feedback

Scrum:
- Sprint-based Agile framework

Kanban:
- Continuous flow
- Visual work management

---

# 9. Best Practices

- Define clear requirements.
- Engage stakeholders early.
- Document decisions.
- Test continuously.
- Review progress regularly.
- Monitor after deployment.

---

# 10. Common Pitfalls

- Unclear requirements
- Scope creep
- Poor communication
- Insufficient testing
- Weak documentation
- Ignoring user feedback
