# Contributing Guide

## Universal Prompt Architect Pro (UPAP)

Thank you for your interest in contributing to the Universal Prompt Architect Pro repository.

This repository is maintained as the canonical source for project documentation, governance, runtime specifications, behavioural standards, knowledge resources, deployment assets, and validation materials.

All contributions should preserve repository integrity, consistency, and long-term maintainability.

---

# Contribution Principles

All contributors should follow these principles:

- Respect the canonical repository structure.
- Preserve documentation consistency.
- Avoid duplicate information.
- Follow repository governance.
- Validate significant changes before release.
- Record meaningful changes in the changelog.

---

# Repository Structure

Contributions must remain within the appropriate canonical folders.

| Folder | Purpose |
|---------|---------|
| 00_Project_Documentation | Project documentation |
| 01_Runtime | Runtime specifications |
| 02_Governance | Policies and governance |
| 03_Behavior | Behaviour rules and workflows |
| 04_Knowledge | Knowledge resources |
| 05_Deployment | Deployment assets |
| 06_Release | Release artefacts |
| 07_Validation | Validation documentation |
| Archive | Historical reference only |

Do not move files between folders unless the repository governance has been updated and the change has been approved.

---

# Before Making Changes

Before contributing:

1. Review the repository structure.
2. Read the governance documentation.
3. Check the latest CHANGELOG.
4. Confirm that your change belongs in the correct folder.
5. Avoid creating duplicate documentation.

---

# Documentation Standards

Documentation should be:

- clear,
- accurate,
- modular,
- version-controlled,
- easy to maintain,
- written in Markdown where appropriate.

Avoid unnecessary duplication between documents.

---

# Repository Governance

Repository governance documents located within:

```
02_Governance/
```

take precedence over contributor preferences.

If governance documentation conflicts with an individual proposal, the governance documentation is authoritative.

---

# Version Control

Contributors should:

- keep changes focused,
- avoid unrelated modifications,
- update CHANGELOG.md when required,
- preserve document history.

---

# Validation

Before proposing significant changes:

- review repository validation documentation,
- confirm structural consistency,
- ensure repository organisation remains unchanged unless explicitly approved.

Validation documentation is located within:

```
07_Validation/
```

---

# Pull Requests

When submitting a pull request:

- clearly describe the purpose,
- explain why the change is necessary,
- reference related issues where applicable,
- confirm that repository structure has not been altered unintentionally.

---

# Issues

If you identify:

- documentation errors,
- governance inconsistencies,
- structural problems,
- validation concerns,

please create a GitHub Issue before making major changes.

---

# Behaviour Expectations

Contributors are expected to:

- communicate respectfully,
- collaborate professionally,
- provide constructive feedback,
- follow repository governance.

Additional behavioural expectations are defined in:

```
CODE_OF_CONDUCT.md
```

---

# Security

Security concerns should be reported according to:

```
SECURITY.md
```

Do not disclose sensitive security information publicly until it has been reviewed.

---

# AI-Assisted Contributions

When using AI tools:

- verify generated content before submission,
- avoid introducing unsupported claims,
- preserve repository terminology,
- respect the canonical folder structure,
- follow repository governance.

AI assistance does not replace contributor responsibility.

---

# Questions

If you are unsure:

- review the governance documentation,
- consult validation documents,
- seek clarification before making structural changes.

---

# Thank You

Thank you for helping maintain the quality, consistency, and integrity of the Universal Prompt Architect Pro repository.
