# Security Policy

## Universal Prompt Architect Pro (UPAP)

---

# Purpose

This document defines the security policy for the Universal Prompt Architect Pro repository.

Its purpose is to promote responsible disclosure, preserve repository integrity, and ensure that security-related concerns are handled appropriately.

---

# Scope

This policy applies to:

- repository documentation,
- governance documents,
- runtime specifications,
- behaviour documentation,
- knowledge packs,
- deployment resources,
- validation documentation.

---

# Security Principles

The repository is maintained according to the following principles:

- Protect repository integrity.
- Preserve canonical documentation.
- Prevent unauthorised structural changes.
- Follow responsible disclosure.
- Validate significant changes before release.

---

# Reporting Security Concerns

If you discover a security issue involving this repository, please report it responsibly.

Examples include:

- accidental exposure of sensitive information,
- repository integrity concerns,
- governance bypass,
- unauthorised structural modifications,
- deployment security issues,
- AI safety concerns.

---

# Responsible Disclosure

Please do **not** publish security-sensitive information publicly before it has been reviewed.

Responsible disclosure helps protect repository users and maintain project integrity.

---

# Repository Integrity

Contributors should never intentionally:

- modify the canonical repository structure without approval,
- remove validation documentation,
- bypass governance procedures,
- replace authoritative documents with unofficial versions.

---

# AI Security

When using AI tools with this repository:

- verify generated content before acceptance,
- avoid introducing unsupported or fabricated information,
- preserve governance rules,
- respect authoritative documentation,
- avoid exposing confidential or unpublished materials.

AI-generated content should always be reviewed by a human before being accepted into the canonical repository.

---

# Confidential Information

The following should never be committed to the repository:

- passwords,
- API keys,
- authentication tokens,
- private credentials,
- confidential organisational information,
- personal data that is not intended for publication.

If such information is committed accidentally, it should be removed following the repository's governance and version control procedures.

---

# Supported Repository State

Security support applies to the current maintained production repository.

Historical or archived materials may not receive updates.

---

# Security Review

Security should be reviewed:

- before major releases,
- after governance updates,
- after structural changes,
- before deployment,
- when introducing new automation or AI workflows.
